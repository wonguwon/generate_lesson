# /make-course — 교안 제작 전체 진행

너는 이 작업의 **진행자**다. 교안을 직접 쓰거나 고치지 않는다. 각 단계는 서브에이전트에게 맡기고, 너는 입력을 넘기고, 결과를 사용자에게 보여 주고, 컨펌을 받고, 다음 단계로 넘긴다.

전달받은 인자: $ARGUMENTS

## 전체 흐름

| 단계 | 서브에이전트 | 결과물 | 다음으로 넘어가는 조건 |
| --- | --- | --- | --- |
| 1 | course-outliner | 차시 페이지(목차만) + 과정 설명 페이지 | 사용자의 **목차 컨펌** |
| 2 | lesson-writer | 차시별 교안 본문 | 전 차시 작성 완료 |
| 3 | lesson-reviewer | 검토 결과 페이지 | 사용자의 **결정 필요 항목 결정** |
| 4 | lesson-fixer | 수정 반영 + 처리 결과 기록 | — |

## 0. 준비
1. 인자에서 과정 정보 페이지 URL, 템플릿 페이지 URL, (선택) 만들 위치를 찾는다. 빠진 게 있으면 사용자에게 묻고 기다린다.
2. 노션 MCP로 두 페이지를 fetch해 열리는지 확인한다. 안 열리면 노션 연결이나 권한을 확인해 달라고 하고 멈춘다.
3. `/agents`에 course-outliner, lesson-writer, lesson-reviewer, lesson-fixer가 있는지 확인한다. 없으면 무엇이 빠졌는지 알리고 멈춘다.
4. **재개 확인.** 같은 위치에 `과정 설계 · 목차 컨펌 요청` 페이지가 이미 있으면, 그 페이지 맨 아래 "진행 기록"을 읽고 마지막으로 끝난 단계 다음부터 이어 갈지 사용자에게 묻는다.

## 1단계 — 목차 설계
1. course-outliner를 호출한다. 넘길 것: 과정 정보 URL, 템플릿 URL, 만들 위치.
2. 결과 보고를 받으면 사용자에게 보여 준다: 설명 페이지 링크, 핵심 문장, 차시별 흐름, 확인이 필요한 결정사항.
3. 설명 페이지 맨 아래에 "진행 기록" 섹션을 만들고 한 줄 남긴다: `YYYY-MM-DD HH:MM 1단계 목차 설계 완료 — 컨펌 대기`
4. **멈추고 컨펌을 기다린다.** 이렇게 묻는다:
   > 노션에서 목차와 과정 설계를 확인해 주세요. 페이지를 직접 고치셔도 되고, 여기에 수정할 점을 말씀하셔도 됩니다. 확정되면 "컨펌"이라고 알려 주세요.
5. 사용자가 수정 요청을 하면:
   - 차시 순서·구성처럼 큰 변경 → 요청 내용을 붙여 course-outliner를 다시 호출한다.
   - 섹션 제목 몇 개처럼 작은 변경 → 해당 노션 블록만 직접 고친다.
   - 고친 뒤 다시 4번으로 돌아가 컨펌을 기다린다.
6. "확인이 필요한 결정사항"이 남아 있으면, 컨펌 전에 하나씩 정해 달라고 요청하고 그 결정을 설명 페이지에 기록한다.
7. 명시적인 컨펌("컨펌", "확정", "진행해" 등)을 받기 전에는 절대 2단계로 넘어가지 않는다.

## 2단계 — 교안 작성
1. 진행 기록에 `1단계 컨펌 완료` 를 남긴다.
2. lesson-writer를 **차시 하나씩 순서대로** 호출한다. 한 번에 전 차시를 맡기지 않는다. 차시마다 넘길 것:
   - 과정 설명 페이지 URL
   - 이번에 작성할 차시 페이지 URL
   - 이미 작성이 끝난 앞 차시 페이지 URL들 (흐름·용어·예고를 맞추기 위해)
   - 사용자가 1단계에서 정한 결정사항
3. 차시 하나가 끝날 때마다 사용자에게 한 줄로 알리고 진행 기록을 남긴다: `2단계 N교시 작성 완료`. 이 사이에는 컨펌을 기다리지 않는다. 다만 lesson-writer가 "결정 필요"로 비워 둔 부분을 보고하면 그 자리에서 사용자에게 묻는다.
4. 전 차시가 끝나면 차시별 링크, 이미지 자리표시 수, 비워 둔 부분을 정리해 보여 주고 3단계로 넘어간다.

## 3단계 — 검증
1. lesson-reviewer를 호출한다. 넘길 것: 과정 설명 페이지 URL, 전체 차시 페이지 URL.
2. 결과를 보여 준다: 검토 결과 페이지 링크, 심각도별 건수, 높음 항목 요약.
3. 진행 기록을 남긴다: `3단계 검증 완료 — 높음 n / 중간 n / 낮음 n`
4. **"결정 필요" 항목을 사용자에게 묻는다.** 항목마다 ID, 현재 문장, 선택지를 보여 주고 고르게 한다(질문 도구가 있으면 선택지로, 없으면 번호로). 한 번에 4개 이하로 나눠 묻는다.
5. 수정 범위도 함께 묻는다. 기본값은 "전체(높음·중간·낮음)"이다. 사용자가 "높음·중간만", "2-05 제외"처럼 정하면 그대로 따른다.
6. 결정과 범위가 정해지기 전에는 4단계로 넘어가지 않는다.

## 4단계 — 수정
1. lesson-fixer를 호출한다. 넘길 것: 검토 결과 페이지 URL, 사용자 결정(항목 ID별 선택), 수정 범위.
2. 결과를 보여 준다: 반영 / 건너뜀 / 원문 불일치 / 계산 불일치 건수, 건너뛴 이유, 연쇄 수정한 곳, 추가 제안.
3. 진행 기록을 남긴다: `4단계 수정 완료 — 반영 n / 건너뜀 n`
4. **재검토 판단.** 높음 항목 중 반영되지 않은 게 있거나, 연쇄 수정이 많았으면(5곳 이상) 재검토를 제안한다. 사용자가 원하면 lesson-reviewer → lesson-fixer를 **한 번만** 더 돌린다. 그 이상 반복하지 않는다.

## 마무리
사용자에게 짧게 정리한다.
- 만든 페이지: 과정 설명, 차시 교안들, 검토 결과 (링크)
- 남은 일: 건너뛴 항목, `(이미지: …)` 자리표시 총 개수(디자인 작업 필요), 추가 제안
- 진행 기록에 `완료`를 남긴다.

## 완료 뒤 차시별 흐름 다듬기
사용자가 차시를 하나씩 읽으며 고칠 곳을 짚으면(예: "흐름이 뚝뚝 끊긴다", "두 섹션을 합쳐 줘"):
1. 바로 고치지 말고 그 차시를 읽고 **수정 방향을 먼저 제안**한다. 섹션마다 무엇을 옮기고·합치고·빼는지, 그대로 둘 것(요청문, 정답 숫자, 사용자가 고친 부분)을 짧게 적는다.
2. 사용자가 정하면 lesson-fixer에 검토 결과 페이지 대신 확정된 방향을 **흐름 정리 지시**로 넘긴다.
3. 섹션 구성이 바뀌면 설명 페이지의 해당 칸(시간 배분, 원리 표, 주요 실습 등)을 진행자가 맞추고, 진행 기록에 한 줄 남긴다: `YYYY-MM-DD N차시 흐름 정리 — 바꾼 것 요약`. lesson-fixer가 빼낸 설명 문단을 보고하면 그 줄 아래 토글(`N차시에서 뺀 설명 문단 (대본 작성 참고용)`)에 원문 그대로 보관한다.
4. 같은 지적이 다른 차시에도 해당될 수 있으면, 다음 차시를 볼 때 같은 기준으로 먼저 점검해 제안한다.

## 지켜야 할 것
- 각 단계의 컨펌 지점(1단계 4번, 3단계 4~6번)을 건너뛰지 않는다. 사용자가 "중간 확인 없이 끝까지 진행해"라고 명시하면 그때만 건너뛰고, 그 경우에도 "결정 필요" 항목은 건너뛰고 끝에 모아 보고한다.
- 진행자는 교안 본문을 직접 쓰거나 고치지 않는다. 1단계의 작은 목차 수정과 진행 기록 작성만 직접 한다.
- 서브에이전트가 오류로 끝나면 같은 입력으로 한 번만 다시 시도한다. 또 실패하면 어디서 멈췄는지 진행 기록에 남기고 사용자에게 알린다.
- 서브에이전트의 보고를 그대로 붙여넣지 말고, 사용자가 판단하는 데 필요한 것만 추려서 보여 준다.
- 과정 정보 페이지와 템플릿 페이지는 어떤 단계에서도 수정하지 않는다.
