# /make-ppt — 교안을 강의용 PPT와 대본으로 만들기

전달받은 인자: $ARGUMENTS

디자인 기준은 **`ppt_design/templates.json` 한 곳**이다. 이 스킬에는 디자인 값을 두지 않는다. 좌표·색·폰트를 스크립트나 스펙에 직접 적지 않고, 디자인을 바꿀 때는 templates.json만 고친다.

아래 명령에서 `PY`는 `.claude/skills/make-ppt/.venv/Scripts/python.exe`, `SCRIPTS`는 `.claude/skills/make-ppt/scripts`다.

## 0. 준비
1. 인자에서 교안을 찾는다. 없으면 묻고 기다린다.
   - 노션 URL: fetch로 읽는다. 안 열리면 노션 연결과 권한을 확인해 달라고 하고 멈춘다.
   - 파일(PDF, Word, 텍스트, Markdown): 읽어서 쓴다.
2. 기관명, 과목명, 담당 강사, 차시(`Day 00`), 분량(표지 포함 장수)을 인자·교안·과정 페이지에서 찾는다. 찾지 못한 항목만 한 번에 묻는다. 분량을 정하지 않았으면 구성표에서 제안한다.
   - 기관명은 기본값이 없다. 이전 덱의 기관명을 가져다 쓰지 않고, 답이 없으면 만들지 않는다.
   - 담당 강사는 이름만 쓴다. "교수" 같은 호칭을 붙이지 않는다.
   - 차시 시간은 교안 속성이나 과정 정보에서 찾고, 없으면 묻는다. 사용자가 "대본 없이"라고 했으면 찾지 않는다.
   - 그 차시의 대본 URL을 받았으면 함께 읽는다.
3. `PY`가 없으면 스킬 폴더에 가상환경을 만들고 `requirements.txt`를 설치한다. 이 PC의 기본 `python`은 다른 앱의 가상환경이라 pip가 없으니 쓰지 않는다.
   ```bash
   py -3 -m venv .claude/skills/make-ppt/.venv
   ```
   ```bash
   .claude/skills/make-ppt/.venv/Scripts/python.exe -m pip install -r .claude/skills/make-ppt/requirements.txt
   ```
4. `ppt_design/templates.json`의 `generation_rules`, `slide_archetypes`를 읽고 규칙을 파악한다. 파일이 없으면 멈추고 알린다.
5. 결과물 폴더를 정한다. `materials/<과정>/ppt/<차시>/`에 `deck.json`과 `.pptx`를 둔다. 같은 이름의 파일이 있으면 덮어쓰지 않고 뒤에 `_v2`를 붙인다.

## 1. 슬라이드 구성표 → 컨펌
1. 교안을 도입 / 본론 / 정리로 나누고, 슬라이드마다 내용에 가장 알맞은 아키타입을 `generation_rules.archetype_selection_hint`로 고른다.
2. 흐름은 표지 → 아젠다 → 도입 → 본론 → 정리 → 마무리다. `generation_rules.deck_flow`를 따른다.
3. 구성표를 표로 보여 준다.

   | 번호 | 구간 | 아키타입 | 제목 | 교안에서 가져올 핵심 내용 | 아이콘 | 예상 시간 |
   | --- | --- | --- | --- | --- | --- | --- |

4. 표 아래에 교안에서 빠지거나 줄인 부분을 따로 적는다. 예상 시간의 합계는 차시 시간과 맞춘다.
5. **멈추고 묻는다.** "구성표를 확인해 주세요. 고칠 슬라이드가 있으면 말씀해 주세요. 이대로 제작할까요?" 사용자가 처음부터 "확인 없이"라고 했으면 건너뛴다.

### 내용을 옮길 때
- 슬라이드의 모든 내용은 교안에서 가져온다. 없는 내용을 지어내지 않는다.
- 한 슬라이드에 메시지 하나, 간결한 명사형·개조식으로 쓴다.
- 한도는 `generation_rules.content_limits`와 `typography.korean_text_rules`를 따른다. 넘치면 글자를 줄이지 말고 문장을 나누거나 슬라이드를 나눈다.
- **표:** 표 아키타입은 없다. 2열 대응표는 `two_column_versus`, 용어 표는 `text_plus_key_point`나 `three_column_card_compare`로 풀고, 줄인 행은 구성표에 적는다.
- **그림:** 노션 이미지는 `notion-get-file-download-urls`로 받아 `deck.json` 옆 `images/`에 두고 `code_or_formula_explain`의 `image`로 넣는다. `(이미지: 설명)` 자리표시는 그림이 없는 자리다. 넣지 않고 구성표에 적는다.
- **실습:** 시간이 교안에 있을 때만 `activity_list_with_time`을 쓴다. 시간을 지어내지 않는다. 시간이 없으면 `process_steps`를 쓴다.
- 과정 원칙은 사용자 메모리를 따른다. 예: 다른 과정을 선수·연결로 언급하지 않는다.

## 2. 제작
1. 컨펌된 구성표를 `deck.json`으로 쓴다. 슬라이드마다 `notes`에 대본을 적는다. 사용자가 "대본 없이"라고 했으면 적지 않는다. 형식은 [references/deck-spec.md](references/deck-spec.md)를 따른다.
2. 아이콘 이름이 맞는지 확인한다.
   ```bash
   PY SCRIPTS/build_deck.py --list-icons 찾을단어
   ```
3. 빌드한다.
   ```bash
   PY SCRIPTS/build_deck.py --templates ppt_design/templates.json --spec deck.json --out 파일명.pptx
   ```

### 대본을 쓸 때
- `.claude/agents/lecture-scriptwriter.md`의 "스타일 기준"과 문체 예시를 읽고 그 말투를 따른다. 슬라이드 수업이므로 그 문서의 대본 구조, 오프닝, `🖥️`·`🎙️` 표기, 노션 작업 규칙은 쓰지 않는다.
- 슬라이드의 글을 그대로 읽지 않는다. 왜 그런지, 언제 쓰는지를 말로 풀어 준다.
- 앞 슬라이드의 마지막 말을 받아 시작하고, 표지에서 인사하고 마지막 슬라이드에서 끝인사를 한다. 끝인사 앞의 다음 시간 예고는 교안에 있는 내용만 말한다.
- 노트에는 말할 내용만 쓴다. 실습 프로그램으로 넘어가는 등 화면이 바뀌는 곳만 `[화면 전환: 노트북 실습 1]`처럼 한 줄로 적는다.
- 분량은 슬라이드의 예상 시간을 따른다. 1분에 약 300자로 잡는다.
- 교안에 없는 사실을 새로 말하면 확인한다. 확인하지 못했으면 쓰지 않고, 강사 경험담은 지어내지 않는다. 경험이 들어가면 좋을 자리는 마무리에 적는다.
- **기존 대본이 있을 때:** 새로 쓰지 않고 슬라이드별로 나눠 옮긴다. `🖥️` 화면 지시와 `🎙️` 표시는 빼고, 교안 화면을 가리키는 말만 슬라이드에 맞게 고친다. 나머지 말투와 문장은 유지한다.

## 3. 검수
1. 규칙 검사를 돌린다.
   ```bash
   PY SCRIPTS/check_deck.py --templates ppt_design/templates.json --deck 파일명.pptx
   ```
   대본을 넣었으면 검사 결과의 말하는 시간이 차시 시간과 맞는지 본다. `오류`는 모두 고친다. `주의`도 문장을 고쳐 없애는 것이 기본이고, 남기면 이유를 보고한다. `deck.json`을 고쳐 다시 빌드한다. `.pptx`를 직접 고치지 않는다.
2. 실제 화면을 확인한다. PowerPoint로 내보낸 이미지를 **전부** 열어 본다.
   ```bash
   timeout 120 PY SCRIPTS/export_png.py --deck 파일명.pptx --out-dir 폴더
   ```
   PowerPoint가 없거나, 다른 파일이 열려 있어 실패하거나, 시간이 초과되면 이 단계를 건너뛰었다고 마무리에 적는다. 사용자의 PowerPoint 창은 닫지 않는다. 닫아도 되는지 물어보고 다시 시도한다.
   스크립트가 못 잡는 것을 본다: 어색한 줄바꿈, 슬라이드에 비해 내용이 너무 적거나 많은 곳, 아이콘이 내용과 맞는지. 고칠 게 있으면 1번부터 다시 한다.
3. 교안과 대조한다. 핵심 내용이 빠지지 않았는지, 교안에 없는 내용이 들어가지 않았는지 슬라이드와 대본을 함께 확인한다.

## 마무리
사용자에게 짧게 정리한다.
- `.pptx` 경로와 장수
- 규칙 검사 결과 한 줄
- 교안에서 줄이거나 뺀 부분
- 대본에서 교안을 말로 보완한 곳, 강사 경험으로 채울 자리
- 그림이 없어 비워 둔 자리, 사용자가 채울 것 (연락처, 표지 이미지 등)

## 수정 요청을 받으면
`deck.json`을 고쳐 다시 빌드하고 3단계를 다시 돌린다. 요청한 슬라이드만 고치고 나머지 내용은 바꾸지 않는다. 슬라이드 내용이 바뀌면 그 슬라이드의 대본을 맞추고, 앞뒤 슬라이드와 말이 이어지는지 확인한다. templates.json의 규칙은 유지한다.

## 지켜야 할 것
- 생성 규칙을 어기면서까지 요청을 맞춰야 할 때는 먼저 사용자에게 알린다.
- 노션 가이드와 templates.json이 다르면 templates.json을 따른다. 가이드는 사람이 읽는 설명이다.
- 교안 페이지는 수정하지 않는다.
