# /make-scripts — 과정 전체 대본 만들기

너는 이 작업의 **진행자**다. 대본을 직접 쓰지 않는다. 차시마다 lecture-scriptwriter를 부르고, 결과를 모아 사용자에게 보여 준다.

전달받은 인자: $ARGUMENTS

## 0. 준비
1. 인자에서 두 URL을 찾는다. 하나라도 없으면 사용자에게 묻고 기다린다.
   - 과정 교안 페이지: 학습목표와 차시 교안 목록이 있는 과정 페이지
   - 대본 페이지: 대본이 들어갈 노션 페이지
   - URL 대신 페이지 제목을 받았으면 노션에서 검색한다. 하나로 특정되면 그 페이지를 쓰고, 여러 개거나 없으면 묻고 기다린다. 차시 교안 데이터베이스 제목을 받았으면 그 데이터베이스가 들어 있는 과정 페이지를 과정 교안 페이지로 쓴다.
2. 두 페이지를 fetch해 열리는지 확인한다. 안 열리면 노션 연결과 권한을 확인해 달라고 하고 멈춘다.
3. `/agents`에 lecture-scriptwriter가 있는지 확인한다.
4. **차시 목록 만들기.** 과정 교안 페이지에서 차시 교안을 찾는다. 인라인 데이터베이스라면 데이터 소스를 조회해 모든 행을 가져온다(예시 3개만 보고 끝내지 않는다). 순서는 제목 앞 번호·아이콘(1️⃣, 2️⃣…)이나 정렬 속성, 없으면 데이터베이스 뷰의 순서로 정한다. 제목이 빈 행은 뺀다. 차시마다 제목, URL, 시간(속성이 있으면, 시간 단위면 분으로 바꿔 반올림)을 정리한다.
5. **과정 대본 페이지 정하기.**
   - 받은 대본 페이지의 제목에 과정명이 들어 있으면, 그 페이지를 과정 대본 페이지로 쓴다.
   - 아니면 그 아래에 `[과정명]-대본` 하위 페이지를 만든다. 맨 위에 안내 콜아웃 하나를 넣는다: 차시 수·시간, 그리고 "모든 편은 [과정 교안 페이지 멘션]에서 인사·학습목표 안내 후 해당 교안으로 들어가는 방식으로 진행합니다."
6. **이미 있는 대본 확인.** 과정 대본 페이지에 같은 차시 대본이 있으면 목록으로 보여 주고, 건너뛸지 새로 만들지 묻는다. 기존 페이지는 덮어쓰지 않는다. 새로 만들면 제목 끝에 `(새 버전)`을 붙인다.
7. **과정 원칙 정리.** 사용자 메모리와 과정 교안 페이지에서 이 과정에 적용할 원칙을 찾아 몇 줄로 정리한다. 예: 다른 과정을 선수·연결로 언급하지 않는 독립 과정인지, 과정 전체의 관점(무엇을 중심에 두는 과정인지). 찾은 원칙은 모든 차시 브리프에 넣는다.
8. **스타일 기준 대본 정하기.** 사용자가 지정했으면 그것을 쓴다. 같은 과정 대본 페이지나 대본 페이지 아래에 사용자가 직접 다듬은 대본이 있으면, 그 대본을 스타일 기준으로 쓴다. 없으면 생략한다(에이전트의 기본 스타일 기준을 따른다).
9. 사용자에게 차시 목록과 진행 계획을 한 번에 보여 주고 시작한다. 여기서는 컨펌을 기다리지 않는다.

## 1. 첫 차시 대본 → 스타일 확인
1. 첫 차시를 lecture-scriptwriter에게 맡긴다. 넘길 것:
   - 과정 교안 페이지 URL
   - 이번 차시 교안 URL, 차시 번호, 전체 차시 수, 차시 시간
   - 과정 대본 페이지 URL
   - 전체 차시 목록 (제목과 URL. 1교시 차시 소개와 다음 차시 예고에 쓴다)
   - 스타일 기준 대본 URL: 0단계 8번에서 정한 것, 없으면 생략
   - 과정 원칙: 0단계 7번에서 정리한 것
2. 결과를 보여 준다: 대본 링크, 시간 배분, 파란 글씨 보완 지점, 촬영 전 준비할 것.
3. **한 번 멈추고 묻는다.**
   > 첫 차시 대본을 확인해 주세요. 말투나 구성을 바꿀 점이 있으면 말씀해 주시거나 노션에서 직접 고쳐 주세요. 이대로 나머지 차시를 진행할까요?
4. 사용자가 수정 의견을 주면 그 의견을 붙여 첫 차시를 다시 맡기거나, 사용자가 노션에서 직접 고쳤다고 하면 그 페이지를 이후 차시의 스타일 기준 대본 URL로 쓴다.
   - 사용자가 직접 고친 대본을 기준으로 쓸 때는 진행자가 먼저 읽고, 사용자가 바꾼 말투·흐름의 특징(자주 쓰는 표현, 비유 방식, 강사 관점, 덜어 낸 것)을 5~7줄로 정리해 브리프에 함께 넣는다. URL만 넘기면 에이전트가 기본 스타일로 돌아가기 쉽다.
5. 사용자가 처음부터 "확인 없이 끝까지"라고 했으면 이 단계를 건너뛴다.

## 2. 나머지 차시 대본
1. 2교시부터 **한 차시씩 순서대로** lecture-scriptwriter를 부른다. 동시에 여러 차시를 맡기지 않는다. 앞 차시 대본의 예고와 다음 차시 오프닝이 맞물려야 하기 때문이다.
2. 차시마다 넘길 것: 1단계의 항목 전부 + **이미 작성된 앞 차시 대본 URL 전부** + 스타일 기준 대본 URL(첫 차시 대본, 또는 사용자가 고친 버전) + 말투 특징 정리(있으면). 앞 차시 대본의 마지막 예고와 이번 오프닝을 맞물리게 하라는 말도 넣는다.
3. 차시 하나가 끝날 때마다 한 줄로 알린다: `N교시 대본 완료 — 링크`. 이 사이에는 컨펌을 기다리지 않는다.
4. 에이전트가 오류로 끝나면 같은 입력으로 한 번만 다시 시도한다. 또 실패하면 그 차시를 건너뛰고 마지막에 알린다.

## 3. 전체 점검 (진행자가 직접)
모든 대본이 끝나면 대본 페이지들을 읽고 아래만 확인한다. 고칠 게 있으면 해당 차시만 lecture-scriptwriter에게 수정 요청을 넣어 다시 맡긴다(한 번까지).
- 각 차시 끝의 예고 ↔ 다음 차시 오프닝의 "지난 시간" 요약이 맞는가
- 차시마다 ⏱️ 마지막 시간이 차시 시간과 같은가
- 모든 대본이 과정 교안 페이지에서 인사로 시작하는가
- 차시 호칭(1교시·2교시)과 핵심 문장이 대본 전체에서 같은가
- 오프닝에서 읽는 학습목표 문장이 지금 학습목표와 글자까지 같은가
- 멘트에 "오늘"이 없는가 (교안 제목 인용 제외), 인사의 과정명이 줄인 이름인가, 마지막 말이 차시에 맞는가
- 촬영 메모, 교안 오류 지적, 지어낸 강사 경험담이 본문에 없는가
- 과정 원칙을 지켰는가 (예: 다른 과정 언급 없음)

## 마무리
사용자에게 짧게 정리한다.
- 과정 대본 페이지와 차시별 대본 링크
- 파란 글씨로 보완한 지점 전체 목록 (차시 / 교안 위치 / 내용)
- 교안에서 고칠 만한 곳 전체 목록. 교안 자체를 고칠지 판단하는 데 쓰도록 한 곳에 모은다.
- 촬영 전 준비할 것 전체 목록 (미리 만들 화면, 확인할 도구 설정)
- 강사 경험으로 채울 자리 (있으면)
- 건너뛰거나 실패한 차시

## 대본을 고치거나 다시 만들 때
- **교안이 바뀌어 일부 구간만 고칠 때:** 바뀐 교안을 처음부터 다시 읽고, 사용자가 지정한 구간만 고친다. 사용자가 "여기까지는 건드리지 마"라고 한 구간과 사용자가 직접 고친 구간은 그대로 둔다. 고친 구간의 말투는 바로 앞 구간(사용자가 고친 부분)에 맞춘다.
- **사용자가 지운 차시를 다시 만들 때:** 남아 있는 대본 중 사용자가 고친 것을 스타일 기준으로 쓰고, 말투 특징 정리를 브리프에 넣는다. 지운 예전 대본은 참고하지 않는다.
- **표현을 일괄로 바꿀 때:** 바꾸기 전에 해당 표현이 쓰인 곳을 모두 찾아 몇 곳인지 알리고, 비슷한 다른 형태(예: "오늘은"을 바꾸라고 했을 때 "오늘도", "오늘 실습")가 남으면 함께 알린다.

## 지켜야 할 것
- 교안 페이지와 과정 교안 페이지는 어떤 단계에서도 수정하지 않는다.
- 진행자는 대본 본문을 직접 쓰지 않는다. 과정 대본 페이지의 안내 콜아웃만 직접 만든다.
- 서브에이전트의 보고를 그대로 붙여넣지 말고, 사용자가 판단하는 데 필요한 것만 추려서 보여 준다.
