# (서비스 이름) - PRD 재료

PRD.md를 만들 때 Claude Code에 읽히는 재료입니다. 내가 정한 것만 적고, 정하지 못한 칸은 비워 두면 Claude Code가 질문합니다.
키 값은 적지 않습니다. 키 이름과 두는 곳만 적습니다.

## 기능 명세
- 기획서의 MVP 목록에서 필수·추후 반영을 나눠 적는다.

## 화면별 요소
- 전체 디자인 방향 한 줄: (예: 깔끔한 업무 도구 느낌, 흰 배경에 포인트 색 하나)

## 데이터 구조
표마다 열, 표 사이의 관계, 중복 기준을 적습니다. 안 적으면 AI가 표를 쪼개거나 합치고, 같은 기록이 두 번 들어갑니다.
- (표 이름): (열, 열, 열 …)
- 관계: (예: 사용자 1 → 주문 여러 행)
- 누구의 기록인가: (예: 표마다 사용자 칸, 화면에서 사용자 번호를 보내지 않음)
- 중복 기준: (예: 사용자와 주문번호 조합은 겹치지 않게, 다시 올리면 덮어쓰기)
- 권한(GRANT): (예: 로그인한 앱과 서버 전용 키만 읽고 쓰기)

## 연동 대상
무엇과 잇는지, 어디서 부르는지, 키를 어디에 두는지 적습니다. 안 적으면 브라우저에서 외부 API를 불러 키가 드러날 수 있습니다.
- (서비스 이름): (하는 일), (부르는 곳: 서버 쪽 코드 등)
- 키 두는 곳: (예: .env.local, 저장소에 올리지 않음)

## 권한
누가 무엇을 보고 고치는지, AI나 외부로 무엇을 보내는지 적습니다. 안 적으면 누구나 모든 기록을 보거나, 개인정보가 든 원본이 밖으로 나갑니다.
- 로그인한 사람: (예: 자기 기록만 보고 고침)
- 로그인 없이: (예: 공유 링크로 한 건만 읽기)
- AI에 보내는 것: (예: 집계값만, 이름·원본 행은 보내지 않음)
- 외부 도구(MCP)로 내보내는 것: (예: 그 사람의 집계값만)

## 완료 기준
숫자·계정·링크처럼 직접 해 보고 맞는지 판단할 수 있는 확인 문장으로 적습니다. "잘 나온다"는 판단할 수 없습니다.
- 숫자: (예: 샘플 파일을 올리면 합계가 미리 계산한 정답과 같다)
- 계정: (예: 다른 계정으로 로그인하면 내 기록이 하나도 보이지 않는다)
- 링크: (예: 로그아웃한 브라우저에서 공유 링크를 열면 그 한 건만 보인다)
- 키: (예: GitHub 저장소 어디에도 키 값이 없다)

## 기술 방식
라이브러리는 이름과 받는 곳까지 적습니다. 안 적으면 사람마다 다른 라이브러리·취약한 버전이 들어옵니다.
- 화면·서버: (예: Next.js(App Router) + TypeScript)
- DB·로그인: 
- 그 밖의 라이브러리: (이름, 받는 곳)
